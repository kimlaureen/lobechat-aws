# Q4 — Build vs buy: self-hosted LobeChat vs SaaS AI assistants

**To:** CTO
**From:** Infrastructure Team
**Date:** 2026-05-12
**Subject:** Build vs buy — self-hosted LobeChat vs ChatGPT Enterprise / Microsoft Copilot

---

## TL;DR

- Self-hosted LobeChat costs **$5.47/seat/month** over three years — 6× cheaper than ChatGPT Enterprise ($61.25) and 5.7× cheaper than Copilot ($30.97) — but that gap buys you a maintenance obligation, not a free lunch.
- The cost argument is secondary. The real case for self-hosting is **private MCP tool integrations**: ssh-exec, aws-resources-operations, and qdrant-mcp enable multi-step automation against internal infrastructure that neither SaaS vendor will ever support, because they cannot see inside your VPC.
- Self-host if data sovereignty is a hard constraint or private infrastructure integrations are required and you have ≥30 active users and ≥0.2 FTE DevOps capacity. Otherwise, buy.

## Lock-in analysis

| | Self-hosted | ChatGPT Enterprise | Microsoft Copilot |
|---|---|---|---|
| Data lock-in | None — Postgres and S3 are fully portable | Conversation history in OpenAI's storage; export via API but no bulk migration path | Conversation data in Microsoft Graph; export possible but graph traversal is complex |
| Identity lock-in | Casdoor OIDC — portable to any IdP | SSO via your existing IdP; no lock-in | Azure AD only; moderate lock-in if M365-native |
| Model lock-in | Swap model via three env vars (OpenRouter → Bedrock → vLLM) | GPT-4o family; model changes are OpenAI's decision, not yours | Copilot uses GPT-4o family within Microsoft's wrapper |
| Tooling lock-in | MCP tools are open protocol — exit by pointing MCPHub at a different host | API-level plugin framework; plugins are not portable across providers | Copilot connectors are M365-specific; rebuilding outside Microsoft costs months |
| **Exit cost** | **~$5–9K** (migration effort) | **~$12–19K** (data export, re-training users, rebuilding plugins) | **$5–8K if already on M365; $500K+ if exiting the full M365 estate** |

The self-hosted exit is the cheapest, but it assumes the exit is from the AI stack, not from AWS. If the company also exits AWS, add migration cost for RDS, S3, and EBS. Copilot's exit cost figure is deceptive — $5–8K is realistic only if the company stays on M365. Disentangling Copilot from Teams, SharePoint, and Exchange is a separate and much larger project.

## Data sovereignty and compliance

For a financial services firm, three regulations are load-bearing:

**DORA (Article 30)** requires financial entities to audit AI service providers, including the right to inspect sub-processors and receive incident reports within defined timeframes. ChatGPT Enterprise and Copilot can provide audit reports, but they cannot give you access to their infrastructure or let you run your own log queries. With self-hosted, the audit right is trivially satisfied — CloudWatch and Secrets Manager audit logs are yours.

**MiFID II** mandates 5-year retention of client communications and the systems that generated them. If client advice is generated or summarised by an AI assistant, that output must be retained with the conversation context. Both SaaS vendors archive conversation history, but the retention format and restore SLA are their decision, not yours. Self-hosted Postgres keeps every message indefinitely; S3 lifecycle rules handle the 5-year requirement explicitly.

**Schrems III risk** is the structural problem. ChatGPT Enterprise and Copilot both process data in US-based infrastructure, with EU availability regions that are contractually accessible to US law enforcement under the CLOUD Act. No EU standard contractual clause survives a targeted US government data demand. For financial data and client conversations, this is not a theoretical risk — it is a documented compliance exposure that your DPO must sign off on. Self-hosted in eu-west-1 on dedicated EC2 keeps data physically and legally within the EEA under GDPR Article 28.

Professional secrecy obligations for financial advisers add a further constraint: client-identifiable information sent to a third-party AI service may constitute a breach, regardless of the vendor's DPA. Self-hosted removes the third party.

## Capability gap

**What self-hosted provides that SaaS cannot:**

- Private MCP tool integrations: `ssh-exec` (run commands on internal servers), `aws-resources-operations` (list, describe, and cross-reference live AWS infra), `qdrant-mcp` (search a private RAG corpus of internal runbooks, post-mortems, architecture docs). Neither ChatGPT Enterprise nor Copilot can reach inside a VPC without a publicly exposed endpoint — which defeats the purpose.
- Multi-step tool chaining: MCPHub aggregates ~10 MCP servers; a single agent prompt can SSH into a server, pull CloudWatch metrics, query the RAG corpus for the relevant runbook, and generate a D2 infrastructure diagram — all in one response. SaaS plugin frameworks execute one tool call at a time.
- Persistent private RAG: the Qdrant corpus is entirely internal, grows with your documentation, and never leaves your infrastructure. ChatGPT Enterprise's file search processes documents in OpenAI's infrastructure.
- Model flexibility: swap Claude Haiku for Claude Sonnet or Gemma 4 in three env vars. SaaS vendors control the model.

**What SaaS provides that self-hosted does not easily match:**

- Guaranteed 99.9% uptime SLA with contractual remedies. The self-hosted app-tier EC2 is a single point of failure — RTO on instance failure is 5–10 minutes, not seconds.
- Native mobile apps, browser extensions, and deep M365 integration (for Copilot). Building equivalent mobile access requires additional engineering.
- Compliance certifications (SOC 2 Type II, ISO 27001) that auditors recognise. Self-hosted requires you to earn and maintain those certifications yourself, or accept that you won't have them.
- Support contracts with defined escalation paths. Self-hosted support is your on-call engineer.

## Recommendation

**Self-host if — and only if — all of the following are true:**

1. Data sovereignty is a hard constraint (regulatory or board-level), not a preference.
2. Private infrastructure integrations (VPC access, internal tooling, proprietary RAG) are required, not nice-to-have.
3. Active user base is ≥30 MAU (below this, fixed ops overhead makes self-hosting more expensive than ChatGPT Enterprise per user).
4. At least 0.2 FTE DevOps capacity is available to own the stack — deployment, monitoring, secret rotation, and incident response.
5. The company has 50–500 employees (too small: ops burden is disproportionate; too large: enterprise SaaS support contracts become non-negotiable).

**Buy if** the use case is general-purpose AI assistance with no private data integrations, or if DevOps capacity is unavailable, or if speed to value is the primary constraint.

For the consultancy context from Q1 — a regulated financial services firm needing AI that can query internal AWS infrastructure and search a private corpus of client runbooks — conditions 1 through 4 are all met. The recommendation is self-hosted.

## Reversal trigger

Two market events would flip this recommendation:

**OpenAI or Anthropic ships a private MCP tunnelling product** — a managed MCP gateway that runs inside your VPC (similar to how Tailscale runs an agent in your network without opening inbound ports). If ChatGPT Enterprise can reach internal tools without exposing them, the primary technical differentiator of self-hosting disappears.

**AWS Bedrock ships managed MCP orchestration inside a VPC** — a managed equivalent of MCPHub running in your own account, with no data leaving the VPC. This would collapse the tooling advantage while preserving data sovereignty and adding the managed SLA.

Monitor both vendors' roadmaps. If either ships within 18 months, the 3-year TCO advantage of self-hosting still applies to existing deployments, but new deployments should default to the managed option.
